ISSUES:
- [moderate] skill-implementer.md has no step that suggests a commit message after finishing all tasks in a session. Users must manually compose commit messages with no summary of what changed. Fix: add a Step 5 (after self-review and scribe calls) that generates a suggested git commit message summarising all files changed and why, drawn from the task checklist and plan.
- [moderate] Scribe/lessons-learned.md is a single monolithic file loaded by agents that may only need a subset of its contents. This wastes context window. Fix: split into three files — Scribe/agent-lessons-learned.md (agent design/behaviour lessons), Scribe/skill-lessons-learned.md (skill authoring lessons), Scribe/general-lessons-learned.md (broadly applicable lessons). Classify all 4 existing entries in lessons-learned.md and migrate to the correct files. Update all agents and skills that reference lessons-learned.md to load only the relevant file(s). Update scribe.md to write to the correct split file based on CLASSIFICATION context (agent-related → agent-lessons-learned.md, skill-related → skill-lessons-learned.md, other → general-lessons-learned.md). Archive the original lessons-learned.md with a deprecation notice rather than deleting it.
- [moderate] Multiple agents call scribe redundantly in a single pipeline run: planner calls scribe after creating a plan, skill-implementer calls scribe after each file change, and reviewer calls scribe after analysis. When a full orchestrator pipeline runs, this results in 3+ scribe captures for a single session. Fix: define a clear ownership rule. Proposed rule — skill-implementer owns the capture for file changes; reviewer owns the capture for review-only runs; planner should NOT call scribe (planner output is already captured when implementer acts on it). Update planner.md to remove its scribe call. Confirm no other agents have redundant calls. Document the ownership rule in orchestrator.md's hard rules section.
- [moderate] No standard error handling protocol exists for agents or skills. When a sub-call fails, a file is not found, or a user rejects an action mid-pipeline, each agent handles this differently or silently. Fix: define a standard error handling protocol and add it to all agent files. Protocol: (a) if a required file is not found, report the missing path and ask the user to resolve before continuing — do not silently skip; (b) if a sub-agent call (A2A) fails or returns an unexpected result, pause, report the error verbatim, and ask the user whether to retry, skip, or abort the pipeline; (c) if the user rejects an action mid-pipeline (says "no", "stop", "abort"), write a session summary of completed tasks so far and stop — do not continue to the next task; (d) classify each pipeline abort as: user-cancelled, file-not-found, or sub-agent-error, and include this in the scribe capture if one was in-progress.
