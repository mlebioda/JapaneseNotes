## 00:00 — update-kanji-list.md (Task 3)

**Called by**: skill-implementer
**Classification**: improvement
**What changed**: Added a `## Pre-flight check` section immediately before the `## Processing order` block. The check verifies that `[file]` exists and is readable before any kanji are processed. If the file is not found, the skill stops immediately with a clear error message and does not fire any web fetches or file writes.
**Why**: Without a pre-flight check, a mistyped filename could cause N web fetches and N filesystem operations before the error is discovered. Fail-fast prevents wasted time and side effects.
**Lesson**: **[Rule]** Any skill that performs N expensive operations (web fetches, file writes) per item must verify its primary input exists before entering the loop — fail-fast costs nothing and prevents difficult-to-undo side effects.

**Called by**: skill-implementer
**Classification**: improvement
**What changed**: Rewrote `## Processing order` to show a two-phase structure: Phase I runs all Step 0 web fetches for every kanji before any file writing, caching results in a `fetch-results` map; Phase II executes Steps 1–4 per kanji using the cached data. Updated Step 0's opening line to reflect Phase I ownership. Updated Step 3's opening line to reference `fetch-results` map instead of "Step 0 returned".
**Why**: The previous order interleaved fetches with file I/O (fetch kanji-1, write kanji-1, fetch kanji-2, …), meaning each fetch was stalled behind the preceding file write. Phase I/II separation decouples network latency from disk I/O and enables the model to issue all fetches before any file write begins.
**Lesson**: **[Pattern]** In a pipeline that alternates between I/O-bound and CPU/disk operations, batching all of one type before the other reduces total wall-clock time — the same principle as double-buffering or read-ahead caching.
